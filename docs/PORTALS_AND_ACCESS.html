Brillanda Portals & Access Architecture

Platform User Roles, Access Flows, Security Specifications, & Portal Architecture

1. Overview & User Roles

Brillanda serves four distinct user groups. All users access the platform through the same main website and sign-in page. Upon authenticating, users are automatically directed to their respective portal based on their role (apps/web/src/portals/{role}).

Portal Audience / Who Primary Responsibilities & Key Capabilities
School Admin The principal or school office Runs the term: configures classes and arms, assigns staff and students, monitors scoring progress, sends nudges, manages unlock requests, and publishes final results.
Teacher Subject teachers Enters scores for assigned classes (tests & exams); real-time auto-calculation of totals/grades; marks classes complete when done.
Parent Parents or guardians Views children's performance, subject breakdowns, grades, class position, and teacher remarks; downloads official report cards; receives notifications.
Super Admin Us, the Brillanda team Platform governance: provisions new schools from trial requests, oversees all registered institutions, monitors system health and usage metrics.

2. How People Get In (Onboarding & Access Control)

Nobody signs themselves up. There is no "Create an account" button anywhere on the platform. That's on purpose: a school's results are private, so every account is created hierarchically by an authority above them.

    A school joins: The school fills in the "Request a trial" form on our website. We (the Brillanda team) review it and create the school tenant. The school's admin then receives an email invite. The admin invites teachers: The admin types a teacher's name and email in the portal, and the teacher receives an email invite. Parents get invited when their child is added: When the admin adds students (individually or via spreadsheet import), each parent's email gets an invite. Parents with no email: They receive a printed paper slip containing an access code instead, and sign in using that code.

Rules & Authentication Security

    Invite Link Expiry: An invite link works for 3 days (72 hours). The recipient clicks it, chooses a password, and gains access. If it expires, they ask the school to send a new one. One Email per Account: One email address maps to exactly one account across the platform. Generic Error Messages: If an incorrect password or an unknown email is typed, the message returned is always identical: "That email and password don't match." This prevents strangers from guessing which emails are registered. Password Reset: If someone forgets their password, the "Forgot password" link emails them a secure reset link.

3. What Each Portal Does

🏫 School Admin Portal

    Sees how far along the term is: how many subjects are in, which classes are ready, and who is behind. Nudges teachers who are behind, and approves/rejects teacher requests to reopen a finished class. Publishes results for a class when all its subjects are done. This locks the scores and emails every parent. Manages classes, arms, students, staff accounts, grading scales, and term dates.

👩‍🏫 Teacher Portal

    Sees strictly their own assigned classes and subjects. Types in scores (first test, second test, exam). Totals and grades work themselves out automatically as they type, with instant saving. Clicks "Mark complete" when a class is finished. To change anything after that, they must request the admin to reopen it.

👨‍👩‍👧 Parent Portal

    Switches seamlessly between multiple children enrolled at the school. Sees each child's average, position in class/arm, every subject's score, and teachers' comments. Opens or downloads official report cards. Gets an automated email notification the moment new results are published.

4. Is There a Super Admin Portal?

Yes, there is a dedicated Super Admin Portal.

    Codebase Location: apps/web/src/portals/super-admin Audience: The internal Brillanda team ("Us"). Functionality:
      Looks after all schools registered on Brillanda. Processes incoming "Request a trial" form submissions from the website (POST /api/v1/trial-requests). Provisions new school tenants and creates initial School Admin accounts. Monitors platform usage, manages tenant subscriptions/status, and controls system-wide settings.
